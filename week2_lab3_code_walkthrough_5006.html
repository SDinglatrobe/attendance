Lab 3: Understand and Test the Attendance Backend with npm and curl

Who does this lab?

This lab is for CSE5006 students only. CSE3CWA students may read it for additional practice. It uses a separate local copy of the Attendance project and does not change the copy used in Lab 1 or Lab 2.

Before you start: your environment

Run every command in the terminal of your Ubuntu virtual machine. This lab uses Node.js, npm, Git and curl. It does not use Render, HTTPS, Nginx, Apache or PM2.

In this lab you will download a clean copy of the Attendance project, install its Node.js dependencies, run the backend locally, and test its routes directly with curl. You will observe successful, duplicate, unknown and invalid student submissions, log in to the administrator route, and inspect the JSON file written by the backend.

What you will achieve

You will understand what npm install and npm start do.

You will run an Express backend locally on port 3000.

You will test backend routes without relying on the browser.

You will verify that a successful request becomes a stored JSON record.

Part 1: Install and verify the required tools

Install Git, curl and Node.js 24. npm is installed together with Node.js. The project requires Node.js 18 or newer.

# Install Git and curl
sudo apt update
sudo apt install git curl ca-certificates -y

# Add the NodeSource repository for Node.js 24
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -

# Install Node.js and npm
sudo apt-get install -y nodejs

# Verify the installed tools
git --version
curl --version
node -v
npm -v

Checkpoint

node -v should show v18 or newer; normally this installation shows v24.x.x. npm -v, git --version and curl --version must also print version information.

Part 2: Download a clean Lab 3 copy

Use a separate folder called attendance-lab3. The first command removes only an earlier Lab 3 practice copy, allowing everyone to start with the same files.

cd ~
rm -rf ~/attendance-lab3
git clone https://github.com/SDinglatrobe/attendance.git attendance-lab3
cd ~/attendance-lab3
pwd
ls

You should see files including server.js, package.json, package-lock.json, 5006.txt, 3CWA.txt and the data folder.

Always work in the project folder

Before running npm or reading the data file, use cd ~/attendance-lab3. Commands such as npm start fail when run from a folder that does not contain package.json.

Part 3: Understand the project definition

cd ~/attendance-lab3
cat package.json

The important fields are:

  • scripts.start is node server.js. Therefore, npm start launches the backend.
  • dependencies lists Express and QRCode, which must be installed before the application can run.
  • engines.node requires Node.js 18 or newer.

Part 4: Install the project dependencies

cd ~/attendance-lab3
npm install
npm list --depth=0

npm install reads package.json and package-lock.json, downloads the required packages, and creates node_modules. Do not upload or manually edit node_modules.

Part 5: Make sure port 3000 is available

The Attendance server uses port 3000. Check whether another program is already listening there:

sudo ss -ltnp | grep ':3000' || true

If this command shows no output, continue. If it shows a PID, inspect and stop that old process:

# Replace PID_NUMBER with the number shown by ss
ps -fp PID_NUMBER
kill PID_NUMBER
sleep 2
sudo ss -ltnp | grep ':3000' || true

Do not stop unrelated system processes

Only stop a process when you recognise it as an earlier Attendance or Node.js test. Ask your tutor if you are unsure.

Part 6: Start the backend

Use a known local administrator password so that every command later in this lab matches the running server.

cd ~/attendance-lab3
ADMIN_PASSWORD=12345678 npm start

The terminal should display:

Attendance system running on port 3000
First class date: 2026-07-14
Time zone: Australia/Melbourne

Keep Terminal 1 running

npm start occupies the terminal because the server is running continuously. Leave this terminal open. Open a second Ubuntu terminal for all curl commands below.

Optional browser check inside Ubuntu: open http://localhost:3000/?week=99. You should see the Attendance Check page and a message stating that test mode is open.

Part 7: Prepare clean and repeatable test data

In Terminal 2, back up the existing practice data and replace it with an empty JSON structure. This affects only ~/attendance-lab3.

cd ~/attendance-lab3
cp data/attendance.json data/attendance.before-lab3.json

cat > data/attendance.json <<'EOF'
{
  "weeks": {}
}
EOF

cat data/attendance.json

Why use week 99?

week=99 is only an isolated test-session number. It is not a real teaching week. Test mode accepts the supplied week value, so using 99 prevents this exercise from mixing with genuine Week 1, Week 2 or other attendance records.

Part 8: Test the backend with curl

Keep Terminal 1 running. Run the following commands in Terminal 2. The current application returns HTTP 200 OK for the four check-in outcomes below; the result is described in the returned HTML body.

Test 1: Request the main page
curl -i "http://localhost:3000/?week=99"

Expected: HTTP/1.1 200 OK, Attendance Check, and the test-mode message.

Test 2: Successful check-in
curl -i -X POST http://localhost:3000/checkin   -H "Content-Type: application/x-www-form-urlencoded"   -d "studentId=99500001&week=99"

Expected: HTTP/1.1 200 OK, Check-in Successful, student ID 99500001, name Adams Isla, and week-99.

Test 3: Duplicate submission
curl -i -X POST http://localhost:3000/checkin   -d "studentId=99500001&week=99"

Expected: HTTP/1.1 200 OK and Already Submitted.

Test 4: Correct format but not in the roster
curl -i -X POST http://localhost:3000/checkin   -d "studentId=99999999&week=99"

Expected: HTTP/1.1 200 OK and Student Not Found.

Test 5: Invalid student ID format
curl -i -X POST http://localhost:3000/checkin   -d "studentId=abc&week=99"

Expected: HTTP/1.1 200 OK and Invalid Student ID.

Part 9: Test administrator authentication with curl

The login route returns a cookie. curl saves that cookie to a file and sends it with the next request.

cd ~/attendance-lab3
rm -f admin-cookies.txt

# Log in and save the administrator cookie
curl -i -c admin-cookies.txt   -X POST http://localhost:3000/admin/login   -d "password=12345678"

# Use the saved cookie to open the protected admin page
curl -i -b admin-cookies.txt   http://localhost:3000/admin

Expected login result: HTTP/1.1 302 Found. Expected protected-page result: HTTP/1.1 200 OK, Attendance Admin, and the record for 99500001.

Part 10: Inspect the stored backend data

cd ~/attendance-lab3
cat data/attendance.json

The JSON should contain a week-99 object and a record for student 99500001 / Adams Isla. This demonstrates the backend flow:

curl request → Express route → roster validation → duplicate check → JSON write → HTML response.

Part 11: Stop the server

Return to Terminal 1 and press Ctrl+C. Then verify in Terminal 2:

curl -i --max-time 2 http://localhost:3000/

Expected: curl reports that it cannot connect. This confirms that the local Node.js backend has stopped.
