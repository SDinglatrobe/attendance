Lab 1: Publish Two Websites on Render (Static + Node.js)

Who does this lab?

This lab is for both CSE3CWA and CSE5006 students. Everyone completes Lab 1 and Lab 2. Lab 3 is an extra CSE5006-only exercise.

Before you start: your environment

All labs assume an Ubuntu machine running in VMware. Open a terminal inside that Ubuntu virtual machine and run every command there.

This lab is done mostly in a web browser (GitHub and Render). The few terminal commands are run inside your Ubuntu virtual machine.

In this lab you take code from your Ubuntu machine, put it on GitHub, and publish it to the internet on Render — twice. First a static website (just HTML/CSS), then a Node.js web application (the attendance app). By the end you will have two public web addresses anyone can open. You will not configure a Linux server in this lab; Render does that for you.

What you will achieve

A GitHub account with two repositories.

A live static site served as a Render Static Site.

A live Node.js attendance app with its own public URL.

A clear understanding of the difference between a Static Site and a Web Service on Render.

Where to get the attendance project

Download or clone it from the attendance repository on GitHub. You can either run git clone on its address, or use the green Code → Download ZIP button and unzip it.

Part 1: Create your free accounts

  1. Create a free GitHub account at https://github.com if you do not have one.
  2. Create a free Render account at https://render.com. On the sign-up page choose Sign in with GitHub so Render can read your repositories.

Why GitHub first?

Render does not take files from your computer directly. It reads your code from a GitHub repository. The flow is always: your Ubuntu machine → GitHub → Render. GitHub is the single source of truth.

Part 2: Install Git and identify yourself

In your Ubuntu terminal, check Git is present and set your identity (used to label your saved versions):

git --version

# If Git is missing:
sudo apt update
sudo apt install git -y

# Tell Git who you are
git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Part 3: Create the static website and push it to GitHub

Start with the simplest possible website. You have two choices for the files:

  • Write your own: a single index.html (the starter file provided with this lab, “This is your first website”, is fine), optionally with a styles.css.
  • Use the class example: the index.html and styles.css from the Week 1 static-site repository.

Put your chosen files in a fresh folder:

# Make a project folder and move into it
mkdir ~/first-website
cd ~/first-website

# Put your index.html (and styles.css, if any) into this folder, then confirm
ls
# You should see: index.html  (and styles.css if you used one)

Create a new empty repository on GitHub (no README, no .gitignore) named first-website. Then connect your folder and push:

# Turn the folder into a Git repository
git init
git branch -M main

# Connect it to the empty GitHub repo you just created
git remote add origin https://github.com/YOUR-GITHUB-USERNAME/first-website.git

# Stage, save a snapshot, and upload
git add -A
git commit -m "My first website"
git push -u origin main

Refresh the repository page on GitHub. Your files should now be there.

If push asks for a password

GitHub does not accept your account password on the command line. When prompted, use a Personal Access Token instead (GitHub → Settings → Developer settings → Personal access tokens), and paste the token in place of the password.

Checkpoint

You should now see your index.html (and styles.css) listed in your GitHub repository in the browser. If they are not there, the push did not succeed — re-run git status and git push origin main.

Part 4: Publish the static site on Render (Static Site)

Because this site is only files (no program runs), the correct Render service is a Static Site.

  1. In the Render dashboard choose New, then Static Site.
  2. Select your first-website repository.
  3. Choose the branch main.
  4. Leave Build Command empty — a plain HTML page needs no build step.
  5. Set Publish Directory to a single dot . because the files are at the top of the repo.
  6. Choose Create Static Site and wait until it reports the site is live.
  7. Open the generated onrender.com address.

Checkpoint: you are live

Your page opens at a public onrender.com address. Send it to a classmate on another device — they can open it from anywhere. It is no longer only on your machine.

Part 5: Get the Node.js attendance project

Now the second, more powerful kind of site: a Node.js application that runs code for each visitor. Get the project from the attendance repository on GitHub:

# Option A: clone with Git (recommended)
git clone https://github.com/SDinglatrobe/attendance.git
cd attendance
ls

# Option B: download the ZIP from the repo's green "Code" button,
# unzip it, then move into the unzipped folder:
cd attendance

Look at package.json to see how the app starts — this is exactly what Render will run:

cat package.json
# Note the important lines:
#   "scripts": { "start": "node server.js" }
#   "engines": { "node": ">=18" }

To deploy it from your own GitHub account, either click Fork on the repository page, or push a copy to a new repo of your own:

# First create an empty repo named "attendance" on your GitHub account, then:
git remote remove origin
git remote add origin https://github.com/YOUR-GITHUB-USERNAME/attendance.git
git push -u origin main

Part 6: Publish the Node.js app on Render (Web Service)

Because this app runs a program, it needs a Render Web Service, not a Static Site.

  1. In the Render dashboard choose New, then Web Service.
  2. Select your attendance repository and branch main.
  3. Render detects the language as Node.
  4. Set Build Command to npm install.
  5. Set Start Command to npm start (this runs node server.js).
  6. Choose the Free instance type.
  7. Choose Create Web Service and watch the deploy logs until it is live.
  8. Open the generated address. You should see the attendance check-in page.

Where did the port come from?

You never typed a port. The code reads process.env.PORT, a value Render sets, and listens there. On your own machine the same code falls back to port 3000. This is why identical code runs in both places unchanged.

Try these pages on your live app:

  • / — the student check-in page.
  • /qr — the weekly QR code.
  • /admin — the admin login (password defaults to 171717 unless you set one).
Set your own admin password (environment variable)

The app reads its admin password from an environment variable so it is not written in the code. Set your own on Render:

  1. Open your Web Service, then choose Environment.
  2. Add a variable: key ADMIN_PASSWORD, value of your choice.
  3. Save. Render redeploys, and your password is now active at /admin.

Part 7: Notice the “stateless” behaviour

Open /admin, then submit one or two test check-ins on the check-in page. They appear in the admin records. Now press Manual Deploy in the Render dashboard (or wait for an idle restart) and look at the admin records again.

Why the records can disappear

The app saves check-ins to a file, data/attendance.json, while it runs. On Render's free, stateless hosting that file is reset to the empty version from GitHub after a redeploy, restart, or idle spin-down — so the check-ins you just made can vanish.

This is expected. Treat the Render demo as a teaching demo, not an official record. After class, open /admin and use Download attendance.json to keep a backup. A real system would store data in a database or on a persistent disk.

Part 8: Update a live site

Updating either site is just the normal Git loop. Render watches your repo and redeploys automatically when you push.

# Make a small edit, then:
git add -A
git commit -m "Update site"
git push origin main

# Render detects the new commit and redeploys automatically.

Completion checklist

  • Your static site is live on an onrender.com address.
  • Your Node.js attendance app is live on its own onrender.com address.
  • You can explain why the static site is a Static Site and the attendance app is a Web Service.
  • You set your own ADMIN_PASSWORD and reached /admin.
  • You observed that runtime data can reset on the free stateless tier, and you downloaded a backup.

Record your two public URLs and your two GitHub repository URLs for submission.
