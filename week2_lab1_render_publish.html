Lab 1: Publish Two Websites on Render (Static + Node.js)

Who does this lab?

This lab is for both CSE3CWA and CSE5006 students. Everyone completes Lab 1 and Lab 2. Lab 3 is an extra CSE5006-only exercise.

Before you start: your environment

Run all terminal commands in an Ubuntu virtual machine. Keep a browser open for GitHub and Render.

This lab uses the recommended 2026 command-line workflow: GitHub CLI (gh) for GitHub authentication and repository creation, and Git (git) for version control, commits, pushes, and updates.

In this lab you will publish two projects:

Ubuntu project folder → local Git repository → private GitHub repository → Render deployment.

You will first build a one-file static website. You will then download the Node.js attendance application, place a clean copy in your own private GitHub repository, and deploy it as a Render Web Service.

What you will achieve

Create a valid HTML page directly from the Ubuntu terminal.

Understand the different jobs performed by Git, GitHub, and GitHub CLI.

Authenticate securely through a browser without manually creating a Personal Access Token.

Create private GitHub repositories from the terminal.

Deploy a Render Static Site and a Render Web Service.

Part 1: Understand Git, GitHub, and GitHub CLI

These three names are related, but they are not the same tool:

  • Git tracks versions of files on your computer. Important commands include git status, git add, git commit, git push, and git pull.
  • GitHub is an online service that stores remote Git repositories and supports collaboration.
  • GitHub CLI (gh) lets you sign in to GitHub and manage GitHub features from the terminal. In this lab, it creates repositories and securely supplies Git with GitHub credentials.

Recommended division of work

Use gh for GitHub login and repository creation. Use git for tracking, committing, pushing, pulling, and updating code. GitHub CLI improves the GitHub workflow; it does not replace Git.

Part 2: Create and secure your GitHub account

  1. Open https://github.com and choose Sign up.
  2. Enter your email address, create a password, and choose a GitHub username.
  3. Complete GitHub's email verification.
  4. Sign in to GitHub in the browser.
  5. Open your profile picture → Settings → Password and authentication.
  6. Enable two-factor authentication and save the recovery codes securely.

Two-factor authentication may be completed in the browser using an authenticator app, passkey, security key, or another option offered by GitHub.

Part 3: Install Git and GitHub CLI on Ubuntu

Run the following commands:

# Update Ubuntu's package list
sudo apt update

# Install Git and GitHub CLI
sudo apt install git gh -y

# Confirm both tools are installed
git --version
gh --version

Part 4: Configure your Git identity

Git records an author name and email address in every commit. Replace the examples below with your own details:

git config --global user.name "Your Name"
git config --global user.email "your-github-email@example.com"

# Check the saved values
git config --global user.name
git config --global user.email

This is identity, not authentication

git config identifies the author of each commit. It does not sign you in to GitHub. Authentication is completed in the next part using gh auth login.

Part 5: Sign in to GitHub from Ubuntu

Run:

gh auth login

Choose the following answers when prompted:

  1. Choose GitHub.com.
  2. Choose HTTPS as the preferred Git protocol.
  3. When asked whether to authenticate Git with your GitHub credentials, choose Yes.
  4. Choose Login with a web browser.
  5. Copy the one-time code displayed in the terminal.
  6. Press Enter to open the GitHub device activation page, or open the displayed address manually.
  7. Sign in to GitHub in the browser.
  8. Enter the one-time code and authorise GitHub CLI.
  9. Complete two-factor authentication if GitHub requests it.
  10. Return to the terminal after GitHub confirms the authorisation.

Now verify the result:

gh auth status

# Explicitly ensure Git uses GitHub CLI credentials
gh auth setup-git

What has just happened?

GitHub CLI completed browser-based authentication and configured itself as a Git credential helper. Normal HTTPS commands such as git push, git pull, and private git clone operations can now use the stored GitHub credentials.

Do not manually create a token for this lab

The browser-based gh auth login workflow handles authentication, including two-factor authentication. Never place authentication tokens in project files, Git commits, screenshots, or LMS submissions.

Part 6: Create your first static HTML website

Copy and paste this complete block. It creates a project folder and a valid one-file website:

# Create and enter the project folder
mkdir -p ~/first-static-html
cd ~/first-static-html

# Create index.html
cat > index.html <<'HTML'
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My First Static Website</title>
</head>
<body>
  <h1>My First Static Website</h1>
  <p>This page was created in Ubuntu and published with Git, GitHub, and Render.</p>
</body>
</html>
HTML

# Confirm the file exists and open it
ls
cat index.html
xdg-open index.html

The Ubuntu browser should display My First Static Website.

Current state

This is still only an ordinary folder on your Ubuntu machine. Git is not yet tracking it, GitHub does not yet contain it, and it is not yet published on the internet.

Part 7: Create the local Git repository and first commit

cd ~/first-static-html

# Create the hidden local Git repository
git init
git branch -M main

# Inspect, stage, and commit the file
git status
git add index.html
git commit -m "Create first static website"
git status

The file is now stored in a local Git commit. It has not yet been uploaded to GitHub.

Part 8: Create a private GitHub repository and push

Remain inside ~/first-static-html and run:

cd ~/first-static-html

gh repo create first-static-html --private --source=. --remote=origin --push

This single GitHub CLI command:

  • creates first-static-html in your GitHub account;
  • sets the GitHub repository to Private;
  • adds the remote connection named origin;
  • pushes the current main branch and its commit.

Check the result:

git remote -v
git status
gh repo view --web

Checkpoint

The browser should show a private repository containing index.html and the commit message Create first static website.

Part 9: Create a Render account and connect GitHub

  1. Open https://render.com.
  2. Choose Get Started or Sign Up.
  3. Sign in with GitHub, or add GitHub under Render's Git Deployment Credentials.
  4. Authorise Render's GitHub application.
  5. Choose access to all repositories or selected repositories.
  6. If you choose selected repositories, include first-static-html.
  7. Return to the Render dashboard.

A private repository must be authorised

If a private repository does not appear in Render, update the repository access granted to the Render GitHub application. Creating the repository on GitHub does not automatically grant Render access.

Part 10: Deploy the static website on Render

A plain HTML website does not run a server program. The correct Render service type is a Static Site.

  1. In the Render dashboard, choose New → Static Site.
  2. Find first-static-html and choose Connect.
  3. Enter a unique service Name, such as yourname-first-static-html.
  4. Set Branch to main.
  5. Leave Root Directory empty because index.html is at the repository root.
  6. Leave Build Command empty because plain HTML requires no build process.
  7. Set Publish Directory to ..
  8. Choose Create Static Site or the equivalent deploy button shown by Render.
  9. Wait for the deploy to complete.
  10. Open the generated onrender.com address.

Private source code, public website

The GitHub repository remains private. The Render URL is public because Render publishes the website produced from the repository.

Part 11: Download and test the attendance application

Use GitHub CLI to clone the public teaching repository:

cd ~
gh repo clone SDinglatrobe/attendance
cd attendance
ls

# Install dependencies and start the local application
npm install
npm start

Open the local URL displayed in the terminal, normally http://localhost:3000. Confirm that the attendance page opens, then return to the terminal and press Ctrl+C.

Part 12: Create your own clean attendance repository

The cloned folder contains the teacher's Git history and remote connection. For this exercise, create a clean repository owned by you:

cd ~/attendance

# Remove the downloaded Git history only
rm -rf .git

# Start your own Git history
git init
git branch -M main
git add -A
git commit -m "Add attendance web application"

# Create your private GitHub repository and push
gh repo create attendance --private --source=. --remote=origin --push

Check the new repository:

git remote -v
git status
gh repo view --web

Why remove .git?

The application files remain, but the original repository history and remote link are removed. You then create a new local history and a new private GitHub repository under your own account.

Part 13: Give Render access to the attendance repository

  1. Return to Render and begin creating a new service.
  2. If attendance is listed, continue to Part 14.
  3. If it is not listed, open the option to configure or manage the connected GitHub account.
  4. In GitHub, add attendance to the repositories accessible by the Render GitHub application.
  5. Save the GitHub settings and return to Render.
  6. Refresh the repository list if necessary.

Part 14: Deploy attendance as a Render Web Service

The attendance application runs a Node.js server, so it must be deployed as a Web Service, not a Static Site.

  1. In Render, choose New → Web Service.
  2. Find your private attendance repository and choose Connect.
  3. Enter a unique service Name, such as yourname-attendance.
  4. Set Branch to main.
  5. Leave Root Directory empty.
  6. Select Node as the Language or Runtime.
  7. Set Build Command to npm install.
  8. Set Start Command to npm start.
  9. Select the available Free instance type for this teaching exercise.
  10. Add an environment variable with key ADMIN_PASSWORD and a value known only to you. If the field is not shown during creation, add it later from the service's Environment page.
  11. Choose Create Web Service or Deploy Web Service.
  12. Watch the deployment logs until Render reports that the service is live.
  13. Open the generated onrender.com address.

Why no port is entered

The server reads process.env.PORT. Render supplies this value to the running Web Service. The same application can use a fallback port such as 3000 when running locally.

Test these paths:

  • / — student check-in page (testing ID: 12345678).
  • /qr — weekly QR code.
  • /admin — administration page using your ADMIN_PASSWORD.

Part 15: Test and download attendance records

  1. Submit one or two test check-ins through the public attendance page.
  2. Open /admin and sign in using your environment-variable password.
  3. Confirm that the test records appear.
  4. Use the administration page's download function to save the attendance data.
  5. Keep the downloaded file as a backup.

Runtime files are not permanent database storage

A redeploy, restart, or instance replacement can remove changes written only to the Web Service's local filesystem. This application is a deployment demonstration, not the university's official attendance system. Production systems should store important records in a persistent database or storage service.

Part 16: Update a live website

After the first upload, the normal workflow is mostly Git. Edit a file, inspect the changes, commit them, and push:

cd ~/first-static-html

# After editing index.html
git status
git diff
git add index.html
git commit -m "Update static website"
git push

Render watches the linked main branch and normally starts a new deployment after the push.

Troubleshooting

git push asks for a username or password

Run gh auth status, then run gh auth setup-git. Confirm that the repository remote uses an HTTPS GitHub address by running git remote -v.

gh repo create says the repository already exists

Choose a different repository name, or open the existing repository with gh repo view first-static-html --web. Do not repeatedly create additional repositories with almost identical names.

The private repository is missing from Render

Update Render's GitHub application permissions and grant it access to that repository. Then refresh the repository list in Render.

The Render Web Service build fails

Check the deployment log. Confirm that package.json is at the repository root, the Build Command is npm install, and the Start Command is npm start.
