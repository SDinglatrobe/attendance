Lab 2: Host Websites on Ubuntu with Nginx, Apache and HTTPS

Who does this lab?

This lab is for both CSE3CWA and CSE5006 students. Everyone completes Lab 1 and Lab 2. Lab 3 is an extra CSE5006-only exercise.

Before you start: your environment

Complete every step inside your Ubuntu virtual machine in VMware. Open Terminal in Ubuntu. Do not run these commands in Windows PowerShell or the Windows Command Prompt.

This is a local-server lab. You do not need Render, AWS, Azure, a public domain name, or a public IP address.

How to edit a configuration file with nano

This lab uses nano, a beginner-friendly terminal editor. Open a file with sudo nano FILE-PATH. Paste the supplied configuration. Press Ctrl+O, then Enter to save. Press Ctrl+X to close nano.

This lab has two separate practical sections. In Section A, you install Nginx and publish a local static HTML website over HTTPS. In Section B, you stop Nginx, install Apache, run the Node.js Attendance application, and use Apache as an HTTPS reverse proxy.

What you will achieve

A local static HTML website served by Nginx.

A self-signed TLS certificate and a working https://localhost Nginx site.

The Attendance Node.js application running locally on port 3000.

Apache serving the Attendance application on standard HTTPS port 443.

An understanding of web roots, configuration files, ports, TLS certificates, reverse proxies and PM2.

Important: Nginx and Apache cannot use the same ports at the same time

Both web servers normally listen on ports 80 and 443. Only one application can own a port at a time. Section A uses Nginx. Section B stops Nginx before starting Apache.

Part 1: Prepare Ubuntu and understand the four ports

Update Ubuntu's package information and install the basic tools used throughout the lab:

# Refresh Ubuntu's list of available software packages
sudo apt update

# Install Git, curl, OpenSSL and nano
sudo apt install git curl openssl nano -y

# Confirm that the tools are available
git --version
openssl version

A port is a numbered network entrance used by an application:

  • 80 — standard unencrypted HTTP.
  • 443 — standard encrypted HTTPS.
  • 3000 — the private local port used by the Attendance Node.js application.
  • 22 — normally used for SSH; it is not required in this local lab.

Section A: Nginx Static Website with Local HTTPS

Part 2: Install and start Nginx

Nginx is a web server. It can read HTML, CSS, JavaScript and image files from a directory and send them to a browser.

# Install Nginx
sudo apt install nginx -y

# Start Nginx now
sudo systemctl start nginx

# Also start Nginx automatically whenever Ubuntu starts
sudo systemctl enable nginx

# Show the current service status
sudo systemctl status nginx --no-pager

Open Firefox or another browser inside Ubuntu and visit:

http://localhost

Checkpoint

The browser should display the default Nginx welcome page. This proves that Nginx is running and listening on HTTP port 80.

Part 3: Create the first Ubuntu local website from the command line

We will not download a website. We will create one directly in Ubuntu so every student starts from the same point.

The website files will be stored in:

/var/www/first-ubuntu-site

/var/www is the normal Ubuntu location for website files. The new folder name is first-ubuntu-site.

# Create the website directory
sudo mkdir -p /var/www/first-ubuntu-site

# Create index.html directly from the command line
sudo tee /var/www/first-ubuntu-site/index.html > /dev/null <<'EOF'
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My First Ubuntu Local Website</title>
  <style>
    body {
      font-family: Arial, sans-serif;
      max-width: 760px;
      margin: 80px auto;
      padding: 30px;
      line-height: 1.6;
      background: #f4f7fb;
    }

    main {
      background: white;
      padding: 35px;
      border-radius: 12px;
      box-shadow: 0 8px 24px rgba(0, 0, 0, 0.10);
    }
  </style>
</head>
<body>
  <main>
    <h1>My First Ubuntu Local Website</h1>
    <p>This HTML page is stored on Ubuntu and served by Nginx.</p>
    <p>The next step is to protect this local website with HTTPS.</p>
  </main>
</body>
</html>
EOF

# Allow Nginx to read the directory and file
sudo chown -R www-data:www-data /var/www/first-ubuntu-site
sudo find /var/www/first-ubuntu-site -type d -exec chmod 755 {} \;
sudo find /var/www/first-ubuntu-site -type f -exec chmod 644 {} \;

# Confirm that index.html exists
ls -l /var/www/first-ubuntu-site

Part 4: Understand where Nginx configuration files are stored

On Ubuntu, Nginx normally uses these two directories:

  • /etc/nginx/sites-available/ — stores site configuration files, including sites not currently active.
  • /etc/nginx/sites-enabled/ — contains links to the sites that Nginx should actually load.

We will create this configuration file:

/etc/nginx/sites-available/first-ubuntu-site

The file has no extension. That is normal for an Nginx site configuration.

Part 5: Generate a self-signed TLS certificate for localhost

A TLS certificate is used by the web server to encrypt HTTPS traffic. A self-signed certificate provides encryption but is not signed by a public Certificate Authority. Therefore, the browser will display a warning. That warning is expected in this local exercise.

sudo mkdir -p /etc/nginx/certs
sudo chmod 700 /etc/nginx/certs

# Create OpenSSL settings for localhost and 127.0.0.1
sudo tee /tmp/localhost-openssl.cnf > /dev/null <<'EOF'
[req]
default_bits = 2048
prompt = no
default_md = sha256
x509_extensions = v3_req
distinguished_name = distinguished_name

[distinguished_name]
C = AU
ST = Victoria
L = Melbourne
O = CSE3CWA-CSE5006
OU = Local Lab
CN = localhost

[v3_req]
subjectAltName = @alt_names
keyUsage = critical, digitalSignature, keyEncipherment
extendedKeyUsage = serverAuth

[alt_names]
DNS.1 = localhost
IP.1 = 127.0.0.1
EOF

# Generate the private key and self-signed certificate
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/nginx/certs/first-ubuntu-site.key \
  -out /etc/nginx/certs/first-ubuntu-site.crt \
  -config /tmp/localhost-openssl.cnf

# Protect the private key and inspect the certificate
sudo chmod 600 /etc/nginx/certs/first-ubuntu-site.key
sudo chmod 644 /etc/nginx/certs/first-ubuntu-site.crt
sudo openssl x509 -in /etc/nginx/certs/first-ubuntu-site.crt \
  -noout -subject -issuer -dates -ext subjectAltName

Certificate and key

.crt is the certificate Nginx presents to the browser. .key is the private key and must never be published or shared.

Part 6: Create the complete Nginx site configuration

Open the configuration file:

sudo nano /etc/nginx/sites-available/first-ubuntu-site

Paste the entire configuration below. Keep the comments beginning with #.

# HTTP server block: redirect HTTP to HTTPS.
server {
    listen 80;
    listen [::]:80;
    server_name localhost;

    # Preserve the requested path while changing to HTTPS.
    return 301 https://localhost$request_uri;
}

# HTTPS server block: serve the static website on port 443.
server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name localhost;

    # Website directory and default home page.
    root /var/www/first-ubuntu-site;
    index index.html;

    # Local certificate and private key.
    ssl_certificate /etc/nginx/certs/first-ubuntu-site.crt;
    ssl_certificate_key /etc/nginx/certs/first-ubuntu-site.key;

    # Permit modern TLS versions.
    ssl_protocols TLSv1.2 TLSv1.3;

    location / {
        # Try a matching file or directory; otherwise return 404.
        try_files $uri $uri/ =404;
    }
}

Save with Ctrl+O, press Enter, and close with Ctrl+X.

Part 7: Enable, test and restart Nginx

# Disable the original default site
sudo rm -f /etc/nginx/sites-enabled/default

# Enable the new site
sudo ln -s /etc/nginx/sites-available/first-ubuntu-site \
  /etc/nginx/sites-enabled/first-ubuntu-site

# Test before restarting
sudo nginx -t

# Load the new configuration and certificate
sudo systemctl restart nginx
sudo systemctl status nginx --no-pager

# -k allows curl to accept this self-signed certificate
curl -Ik https://localhost

Never restart after a failed configuration test

If sudo nginx -t reports an error, reopen the named file, correct the reported line, save it, and test again.

Open https://localhost in the Ubuntu browser. Accept the self-signed certificate warning for this local lab.

Nginx success checkpoint

The address remains https://localhost and the page displays My First Ubuntu Local Website. The warning is expected because the certificate is self-signed; HTTPS encryption is still operating.

If Firefox browser shows "Risk" warning, you can click "Advanced" option to accept the risk. 

Section B: Apache HTTPS Reverse Proxy for Attendance

Part 8: Stop Nginx before starting Apache

sudo systemctl stop nginx
sudo systemctl disable nginx
sudo systemctl status nginx --no-pager

inactive (dead) is correct. Nginx has released ports 80 and 443.

Part 9: Install Apache and enable the required modules

sudo apt install apache2 -y

# TLS, reverse proxy, forwarded header and redirect modules
sudo a2enmod ssl
sudo a2enmod proxy
sudo a2enmod proxy_http
sudo a2enmod headers
sudo a2enmod rewrite

sudo systemctl start apache2
sudo systemctl enable apache2
sudo systemctl status apache2 --no-pager

Open http://localhost. The Apache default page should appear, proving Apache now owns port 80.

Part 12: PM2 — what it is, why it is needed and how to use it

PM2 is a process manager for Node.js applications. Apache does not execute Attendance. Apache forwards requests, while the Node.js process must continue running independently on port 3000.

Without PM2, npm start stops when the terminal closes, the process crashes, or Ubuntu restarts. PM2 runs it in the background, provides logs and status, restarts failed processes, and can restore them after reboot. 

sudo npm install -g pm2
cd ~/apps/attendance

# Start npm start under PM2 with the required values
PORT=3000 ADMIN_PASSWORD=12345678 \
  pm2 start npm --name attendance -- start

pm2 status
pm2 logs attendance --lines 50

Press Ctrl+C to leave the log view; the application remains running.

curl -I http://127.0.0.1:3000

# Save the process and configure restoration after reboot
pm2 save
pm2 startup systemd

# Copy and execute the exact sudo command printed by PM2.
# Then save again:
pm2 save

Useful commands:

pm2 status
pm2 restart attendance
pm2 stop attendance
pm2 start attendance
pm2 logs attendance

PM2 with Nginx or Apache

PM2 performs the same application-management role behind either server. Nginx or Apache owns HTTP/HTTPS; PM2 keeps Node.js running.

Part 14: Create the Apache site configuration

Apache stores available sites in /etc/apache2/sites-available/. Apache site files normally end with .conf.

sudo nano /etc/apache2/sites-available/attendance-local.conf

Paste the complete commented configuration:

# HTTP virtual host: redirect every request to HTTPS.
<VirtualHost *:80>
    ServerName localhost

    RewriteEngine On
    RewriteRule ^ https://localhost%{REQUEST_URI} [R=301,L]
</VirtualHost>

# HTTPS virtual host: terminate TLS and forward to Node.js.
<VirtualHost *:443>
    ServerName localhost

    # Enable TLS and identify the certificate files.
    SSLEngine on
    SSLCertificateFile /etc/apache2/certs/attendance-local.crt
    SSLCertificateKeyFile /etc/apache2/certs/attendance-local.key

    # Preserve browser host information.
    ProxyPreserveHost On

    # Never operate as an open forward proxy.
    ProxyRequests Off

    # Forward all paths to Attendance on local port 3000.
    ProxyPass / http://127.0.0.1:3000/
    ProxyPassReverse / http://127.0.0.1:3000/

    # Tell the application that the browser used HTTPS.
    RequestHeader set X-Forwarded-Proto "https"

    # Dedicated files for access and error messages.
    ErrorLog ${APACHE_LOG_DIR}/attendance-local-error.log
    CustomLog ${APACHE_LOG_DIR}/attendance-local-access.log combined
</VirtualHost>

Save with Ctrl+O, Enter, and close with Ctrl+X.

Part 17: Understand the completed architecture

Browser
  |  HTTPS: https://localhost on port 443
  v
Apache
  |  TLS ends here; request is reverse-proxied
  v
Node.js Attendance
  |  private local service: 127.0.0.1:3000
  v
Response returns through Apache to the browser
  • Apache owns ports 80 and 443 and manages TLS.
  • Node.js executes the Attendance application.
  • PM2 keeps the Node.js process running.
  • The self-signed certificate encrypts the local browser-to-Apache connection but is not publicly trusted.

Part 18: Troubleshooting

# Which programs own ports 80, 443 and 3000?
sudo ss -ltnp | grep -E ':80|:443|:3000'

# Apache configuration, service and logs
sudo apache2ctl configtest
sudo systemctl status apache2 --no-pager
sudo journalctl -u apache2 -n 50 --no-pager
sudo tail -n 50 /var/log/apache2/attendance-local-error.log

# Attendance process and direct backend test
pm2 status
pm2 logs attendance --lines 100
curl -I http://127.0.0.1:3000

If Apache reports that port 80 or 443 is already in use:

sudo systemctl stop nginx
sudo systemctl restart apache2

If Apache shows 503 Service Unavailable, Apache is running but Attendance is probably not listening on port 3000:

pm2 restart attendance
pm2 status
curl -I http://127.0.0.1:3000
